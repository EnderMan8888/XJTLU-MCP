# eBridge 成绩查询（本地开发版）

eBridge 成绩查询随 XJTLU-MCP V2.0 提供。

## 使用

1. 打开「eBridge 教务」，使用首页公共学校账号完成连接。
2. 进入「成绩查询」。已连接且首次进入时自动读取，也可以点击「查询成绩」或「刷新成绩」。普通启动只读取原有教务信息，不主动查询成绩。
3. 「当学年分项成绩」来自 Academic Records → Component Marks，按课程显示考核项目、考核类型、比重和学校原始分数。
4. 「完整成绩记录」来自 Full Academic Records，显示学年、学期、课程、学分、课程类型、总评、等级和次数。点击「查看分项」展开该条历史课程记录的考核成绩。
5. 可按学年筛选，或搜索课程代码、名称、考核项目；「学校原页」打开当前类别对应的官方页面。

分项与总评互相独立，不根据部分分项推算总评、平均分或 GPA。空白显示「暂无成绩」，真正的 `0` 原样保留；等级、状态、比重沿用学校文本。学校没有提供的字段显示为空缺，不猜测通过、缺考或成绩发布情况。

## 读取与边界

- 复用现有 `persist:xjtlu-ebridge` 会话、公共账号和 UIM 认证，额外验证仍由用户在官方窗口完成。
- 从当前会话实际观察到的 Academic Records、Component Marks、Full Academic Records 链接导航，不构造学生 ID 或签名参数，不打开 MC 申请等写入入口。重新进入裸域名可能切换 SITS 门户会话，因此成绩查询复用已观察的签名入口。
- 成绩页面是独立读取任务，与课程/考试查询共用同一个学校窗口并串行处理；同时发起的成绩查询复用同一个任务。
- 完整成绩记录的每个课程行内还包含分项表。解析限定直属表头和课程行，分开处理外层总评与内层分项，避免遗漏课程或混入其他分数。
- 两类成绩分别记录成功时间和错误，失败保留上次结果；认证过期会提示重新连接。关闭学校窗口停止读取，断开或实际换账号时立即清除该来源内存数据。
- 只返回课程和成绩字段；学校账号、密码、原始链接与签名参数保留在主进程，不通过页面接口返回，不写入日志。成绩仅在本次运行的内存中保存。
- 本轮没有新增成绩 MCP 工具，现有五个工具的返回范围保持不变。

## 实测与验证（2026-11-17）

- 通过正式服务真实读取 Component Marks：7 门课程、19 项考核，其中当时 2 项分数非空；Full Academic Records：19 门课程、50 项历史分项记录。学年分别包含 2026/27 和 2025/26。这些数量只代表当次账号与页面，不代表其他账号或未来结果。
- 两类读取均成功；重复请求合并，返回模型未包含学校会话链接。诊断只输出结构和条数，没有将具体成绩、账号或会话写入测试和日志。
- 类型检查、生产构建通过；`ebridge-grades.test.ts`、`ebridge.test.ts` 和 `ebridge-day.test.ts` 共 15 项定向检查通过，覆盖空白与零分、课程次数、来源字段边界、成绩入口、现有考试和课表行为。
- 未做全量回归，其他学年/学校未来改版仍需后续观察。成绩功能新增时界面控制被误按 Esc 停止，未完成成绩新界面的专项目视检查；后续界面控制已恢复并完成通用滚动布局核对，成绩筛选和展开交互仍待专项核对。

实现位于 `src/providers/ebridge-grades.ts`、现有 eBridge 主进程服务及受限通信接口、`src/renderer/src/EbridgeGradesPage.tsx`。临时诊断入口 `.scratch/ebridge-grades-check/` 不上传。
