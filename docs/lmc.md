# Learning Mall Core 接入（本地开发版）

Learning Mall Core 的课程、通知和原文件下载随 XJTLU-MCP V2.0 提供。

## 使用

1. 在「账号与设置」保存学校账号，从首页或侧栏进入「Learning Mall Core」。
2. 点击「连接 LMC」。程序使用自己的 Core 会话，经学校 SAML / UIM 登录；额外验证交由用户在学校窗口完成。
3. 搜索并选择课程，按章节查看 Module 活动。普通资料点击「下载」；文件夹点击「查看文件」后下载具体文件。
4. 下载时使用系统保存窗口选择位置，完成后可以「显示文件」。支持查看进度和取消，同时处理一个下载，最近 20 条记录仅保存在本次运行中。
5. Notification 默认读取最近 20 条，可「加载更多」，本轮最多保留 500 条。支持定位原帖的论坛通知可点击「查看附件」，再选择要下载的文件。附件查询使用学校的只读讨论接口。[Moodle 接口定义](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/mod/forum/db/services.php)
6. 在课程内选择「Grades」查看个人成绩表。作业、测验、互评可点击「成绩与提交」读取活动的个人提交结果。作业可显示学校列出的历史提交。测验优先读取最近最多六次可回顾作答的原页，同一活动内的各次得分会标明来自「单次回顾页」或「作答列表」。互评可显示自己那次提交的已公布互评分数。其他与成绩表关联的活动仍可查看相应 Grades 条目。

左侧课程列表支持「最近访问」与「名称 A–Z」，默认最近访问，并在本机记住选择。最近访问使用 Core 自己返回的课程访问顺序，刷新课程后更新，不按本地点击历史猜测；名称排序只作用于界面中的列表。2026-11-17 已只读核对 Core 原版课程总览的排序设置也是最近访问，程序保留的 23 门课程顺序与学校返回结果一致；没有修改学校排序偏好。

通知页提供「隐藏账号登录提醒」，默认开启并在本机记住选择。只过滤标题为 `New sign in to your Learning Mall Core account` 的已加载通知（忽略大小写及多余空白），显示本次隐藏条数；不修改学校数据或未读总数。当前一页全部隐藏时仍可加载更多，关闭选项即可查看登录提醒。

通知使用紧凑列表：标题、已读标签与课程/来源/作者/时间分别排版，正文默认两行摘要，点击「展开详情」按段落阅读。仅对已识别的 Moodle 论坛邮件移除重复导航、头像占位和邮件操作尾部；其他格式保留正文并规范空白。全部以纯文本展示，不渲染学校 HTML，不改动缓存原文或学校已读状态。

资料直接保存为学校原文件，不提取 PDF、Office、HTML 或压缩包的文档正文，不进行 OCR。课程目录在作业名称后显示学校提供的开放时间和截止时间，沿用学校显示的时间格式。缺项显示「未读取到」。瓷砖课程只在目录列出作业时，尝试读取对应的课程活动卡片。用户点开作业的学校原页时，也会读取该页显示的时间。讨论、测验等保留学校原页入口。学校原页的正常访问可能影响活动完成状态，程序没有作业提交、发帖或通知标为已读功能。

## 数据与连接

- 官方入口：`https://core.xjtlu.edu.cn/`。复用公共学校账号，独立会话为 `persist:xjtlu-core`，不读取普通浏览器 Cookie。LMC 默认按需连接，普通启动不会自动抓取课程资料。
- 课程来自学校当前用户的已选课程只读接口，按 50 条分页，最多 500 门；成功刷新清理已不在列表中的课程缓存。只有选择课程或展开文件夹才读取对应目录。瓷砖课程会等待异步章节索引，再合并主页及侧边目录，包含首页未展开的每周资料。
- 通知使用当前用户的只读接口，不调用已读状态修改接口；在应用内展开正文不修改学校已读状态。「打开原文」只使用已观察到的学校阅读页面入口。
- 每类数据独立记录更新时间和错误，刷新失败保留上次结果；不会把失败当作空目录。课程目录和通知仅保存在本次运行内存中，文件只保存到用户选择的位置。
- 断开 LMC 清除该服务的会话和内存数据，并取消下载，公共学校账号保留。更换学校账号时清除旧 LMC 数据和在途任务。
- 文件地址仅在主进程内部登记。界面及 MCP 通过登记的资料 ID 发起下载，只接受当前学校窗口发起且匹配本次请求的 Core 文件。MCP 可传用户指定的 `savePath`，桌面下载仍使用保存窗口。
- 学校窗口不开放 Node，使用隔离环境，仅允许 Core / UIM 的 HTTPS 导航。普通资料兼容直接重定向到文件和显示预览的页面；不支持外部网站下载或整文件夹 ZIP 打包。
- 个人成绩表、成绩反馈和提交状态按需读取，随断开或更换账号清空，仅保留在本次运行内存中。原页访问可能被学校计入活动浏览进度。读取范围以当前账号可见内容为准。
- MCP 提供 LMC 通知、课程列表、课程目录、成绩和原文件下载。`get_module_contents` 会一并返回已读取到的作业时间。成绩、作答记录和提交状态通过 `get_lmc_grades` 查询。[MCP 工具清单](mcp.md#工具列表)

## 已验证的范围（2026-11-17）

- 类型检查、生产构建通过；LMC 和 MCP 两个定向测试文件共 24 项通过，使用虚构数据覆盖来源校验、异步章节索引、通知字段兼容、只读接口、缓存语义及现有五个工具调用。
- 使用程序现有会话真实连接，课程接口返回 23 门并完成分页，通知返回最近 20 条；连续只读刷新前后未读数量保持不变。早期首页的 12 个入口不是全部课程数量。
- 实际读取多个课程的章节与活动，抽样包含学校实际为空的文件夹，以及一个包含 9 个文件的文件夹。目录失败与已确认的空目录分别处理。
- 瓷砖课程实测合并 4 个有活动的章节、43 个活动，其中 33 个资料入口；修复了只读取首页 7 个活动而遗漏周课件的问题。没有活动的章节不显示，不把章节数量当作教学周数。
- 通过生产服务真实下载普通资源 PDF（170,523 字节）及文件夹内 PDF（12,868 字节），验证完成状态和文件头，未提取文档内容。诊断入口在生产服务配置系统保存窗口后，仅将测试下载目的地改为本地临时目录；检查后删除这些测试文件。
- 尚未验证全部课程、全部文件格式、所有会话自然过期或验证码分支，不代表所有文件都能下载。外部工具和文件夹压缩下载不在当前范围。

临时诊断位于忽略目录 `.scratch/lmc-live-check/`，不上传。生产实现为 `src/main/lmc-service.ts`、`src/providers/lmc.ts`、`src/shared/lmc.ts` 和 `src/renderer/src/LmcPage.tsx`。
