# Windows 打包、升级与卸载流程

从下一次打包开始，每个 Windows x64 版本同时提供完整安装版、完整解压版和 Lite 更新包。完整安装版和解压版都提供卸载入口，由用户决定是否保留本机数据。无论选择哪种数据处理方式，卸载流程都移除本工作台安装的校园 Agent 插件和连接器。

本文是下一次打包的实施说明。V2.1 已发布的附件继续以当时的说明为准。[V2.1 发布说明](../releases/v2.1.0.md)

## 构建与发布

| 产物 | 文件名 | 用户使用方式 |
| --- | --- | --- |
| 安装版 | `XJTLU-MCP-<version>-win-x64-setup.exe` | 双击安装。首次安装可选目录和桌面快捷方式，已安装时在原目录升级。安装后创建开始菜单快捷方式，并登记到 Windows「已安装的应用」。 |
| 解压版 | `XJTLU-MCP-<version>-win-x64.zip` | 完整解压后运行 `XJTLU-MCP.exe`。可从解压目录运行 `Uninstall.exe` 清理。 |
| Lite 更新包 | `XJTLU-MCP-<version>-win-x64-lite-setup.exe` | 双击执行兼容性检查，复用已安装版本中的 Electron，在原目录更新。 |
| 校验文件 | `SHA256SUMS.txt` | 为完整安装 EXE、完整解压 ZIP 和 Lite EXE 分别提供 SHA-256 校验值。 |

1. 在外层工程沿用 `npm run package:win` 作为打包入口。先运行一次生产构建。从同一份应用代码、生产依赖和插件资源生成三种包。完整安装版和解压版随附 Electron，Lite 复用兼容的运行环境。
2. 将卸载入口 `Uninstall.exe` 放在程序目录。安装版登记的 Windows 卸载项指向同一入口。解压版通过其目录内的入口执行清理。
3. 保持版本号、文件名和发布说明一致。发布说明列出三种包、Lite 所需环境以及升级和卸载说明。打包失败或缺少任一产物时，发布任务失败并提示缺失项。
4. GitHub Actions 在同一个版本的 Release 上传三种包和校验文件。校验值从 CI 实际上传的文件计算。以外层工程为发布来源，依赖及 Electron 的许可证随相应文件保留。
5. 发布后只核对 SHA-256 时，使用 GitHub Release 附件报告的摘要与同一次 CI 构建生成的 `SHA256SUMS.txt` 比对。需要时只取校验文件。要验证下载可用性、实测安装，或缺少可信的远端摘要时，再下载相应的 EXE 或 ZIP。CI 包和本地包分别核对各自的校验值。

## 安装与原地升级

1. 安装器在复制任何文件前，按固定的应用标识检查当前 Windows 用户的安装登记，并读取已登记的安装路径。仅使用过解压版或已存在 AppData 数据时，按首次安装处理。
2. 首次安装时显示「选择安装位置」页面，默认填入 `%LOCALAPPDATA%\Programs\XJTLU-MCP`，允许用户通过「浏览」选择其他可写目录，例如 `D:\Apps\XJTLU-MCP`。向导提供「在桌面创建快捷方式」复选框，默认不勾选。勾选后才创建桌面快捷方式，开始菜单快捷方式照常创建。安装成功后登记实际使用的路径，供后续升级和卸载使用。
3. 检测到已安装时，显示原安装路径并在该目录原地更新，跳过目录选择。安装器先退出正在运行的工作台和托盘进程，再替换程序文件，更新原有快捷方式和卸载登记。升级保留已有的桌面快捷方式，桌面上没有本应用的快捷方式时维持现状。原路径在其他盘时同样沿用。登记的路径无法确认时，提示安装记录异常，暂停覆盖操作。
4. 升级保留同一用户的 `%APPDATA%\XJTLU-MCP-AMS\` 数据和 Agent 配对设置。卸载程序也使用已登记的实际路径来定位安装文件。

### Lite 更新前的环境校验

1. Lite 在写入任何程序文件、停止工作台或更改安装登记前，定位当前用户已登记的安装目录，检查其中的 Electron 版本、Windows 架构和必需的运行文件。兼容规则以本次打包实际使用的 Electron 版本为准。
2. 找不到现有安装，或者运行环境缺失、损坏或版本不兼容时，停止升级并显示「需要完整安装版，请下载同版本的 Setup.exe」。保留原程序及数据，让用户自行取得完整版。
3. 校验通过后走原地升级流程，更新应用代码、生产依赖、插件资源和需要随版本更新的工具文件，保留现有 Electron 及其依赖。更新后的安装文件清单须包括复用的运行时文件，供后续升级与卸载使用。
4. 即使新版升级了 Electron，也继续生成 Lite，由它在校验时引导不兼容的用户使用完整安装版。

### Windows 安装权限

用户实测安装时遇到目录访问被拒绝，提权后才能访问目标目录。后续打包须覆盖需要管理员权限的目标目录，包括自选安装路径和已登记的原升级路径。

- 复制文件、修改旧安装或变更登记前检查目标路径的写入权限。当前用户能写入时直接安装，需要管理员权限时显示 Windows UAC 提示。用户拒绝提权或提权后仍无法写入时，显示目标路径及失败原因并停止安装或升级。
- 提权仅用于需要管理员权限的安装文件操作。安装登记、快捷方式、本机数据及 Agent 配对仍归原操作用户。通过另一管理员账号批准 UAC 时，也须保留原用户和原安装路径。工作台日常启动使用普通权限。

## 卸载时用户看到的流程

1. 从 Windows「已安装的应用」或程序目录的 `Uninstall.exe` 打开卸载程序。开始前显示即将移除的程序和已识别的校园 Agent 接入项。
2. 选择「保留本机数据」或「删除本机数据」。默认选中保留。两个选项都清理校园 Agent 插件、连接器和专用配对配置。继续使用的 Agent 客户端在重装工作台后需要重新接入。
3. 完全退出工作台及其托盘进程，停止 MCP 服务。卸载期间使用安装和配对时的 Windows 用户身份操作，以便访问该用户的客户端配置和数据目录。
4. 逐一卸载已识别的校园接入项并核对结果。客户端仍占用配置时，提示用户退出该客户端后重试。卸载界面保留未完成项和重试入口。
5. 移除所选程序副本的已知文件。安装版同时移除本应用的快捷方式和 Windows 卸载登记。按照用户的选择处理 AppData，最后报告已移除、未安装和仍需处理的项目。

| 用户选择 | 本机数据处理 |
| --- | --- |
| **保留本机数据（默认）** | 保留账号、学校会话、应用设置、校务缓存及应用自己的 `mcp-access.bin`。移除客户端里的配对记录和已解除登记的插件资源。重装后可继续使用留存数据，学校会话过期时按学校提示登录。 |
| **删除本机数据** | 删除当前用户的 `%APPDATA%\XJTLU-MCP-AMS\`，清除保存的账号、学校会话、设置、缓存和应用自己的 MCP 密钥。确认界面显示该目录，并告知同一用户下的安装版、解压版共用这份数据。 |

同一用户覆盖升级或从解压版迁移到安装版时，沿用现有 AppData 和 Agent 配对。升级流程只换程序文件，旧程序目录曾被登记为插件来源时，先将已安装插件指向可用的新来源，再移除旧目录。两种卸载选择都保留用户另外下载的 LMC 资料及其他自有文件。[本机数据说明](runtime-data-and-environment.md)

## 校园 Agent 接入清理范围

现有「Agent 连接」页已经为五个客户端提供逐项卸载入口。完整卸载应复用这些操作并补齐登记、缓存和配对信息清理。通过已知插件 ID、配置身份及安装记录核对归属，同名条目需确认指向本项目。手工配置、归属不明确或客户端不提供自动移除方式时，列出对应界面和手动移除步骤。

| 客户端 | 要清理的项目 |
| --- | --- |
| ChatGPT / Codex | 卸载 `xjtlu-campus@xjtlu-local`，清理本项目的 `xjtlu-local` 目录登记及相应插件缓存和本机插件资源。 |
| DeepSeek Harness | 从对应 profile 移除 `@local/xjtlu-mcp`，清理该校园插件的凭据引用和随工作台生成的插件副本。 |
| 腾讯 WorkBuddy | 从配置移除本项目的 `mcpServers.xjtlu`，以及仅与该连接对应的信任记录。 |
| Xiaomi MiMo Code | 移除校园插件登记及 `mcp.xjtlu`，识别本项目曾使用的旧插件 ID。 |
| Kimi Code | 从工作台写入的配置移除本项目的 `mcpServers.xjtlu`。 |
| 豆包 | 当前由用户在豆包中手动添加。卸载界面提供「管理 → 连接器」的移除说明，用名称和服务地址帮助用户核对所属条目。 |

- 删除本项目写入、且已无保留连接引用的 Windows 用户环境变量 `XJTLU_MCP_TOKEN` 和旧版 `XJTLU_CODEX_MCP_TOKEN`。删除单条客户端凭据或配置时保留该文件内其余记录。
- 保留 Agent 客户端本身、其他插件、聊天记录和通用设置。逐项卸载可安全重试。条目不存在时记为「未安装」，无法核对或移除时显示「待处理」以及原因，留存完成清理所需的入口和信息。
- 程序文件和 AppData 的清理按已确认的绝对路径执行。解压版使用包内文件清单识别可删除项，保留用户放在同目录的其他文件。

## 下次打包的验收

用隔离的 Windows 用户配置和虚构数据检查以下路径。

- 一次打包生成同版本的完整安装 EXE、完整解压 ZIP、Lite 更新 EXE 和校验文件，两个完整包均可独立启动。
- 用 Lite 升级兼容的已安装版本，确认升级后能运行，并保留运行时、用户数据和 Agent 配对。另测未安装、运行时缺失和版本不兼容，确认提示使用完整版，并保留原文件和登记。
- 分别验证首次安装使用默认目录和自选目录。用新版 EXE 升级自选目录中的旧版，确认安装器识别原路径、跳过选目录并原地更新，Windows 中只保留一条安装记录。
- 验证普通权限可写目录及需要提权的目录。受保护目录覆盖首次安装与原地升级。取消 UAC 时，原程序、用户数据和安装登记继续可用。
- 分别验证勾选和取消勾选「在桌面创建快捷方式」。确认两种选择下的桌面结果正确，原地升级保持该状态，卸载移除安装器创建的快捷方式。
- 安装版能从 Windows 设置和程序目录打开卸载，解压版能从自己的目录打开卸载。
- 覆盖安装或从解压版迁移后，原有应用数据和可用的校园 Agent 连接得以沿用。
- 分别验证保留与删除本机数据。两条路径都移除测试用校园接入项，并保留其他插件、其他配置和已下载文件。
- 模拟插件未安装及客户端占用配置的情况，检查结果提示和重试。豆包等手动项按实际状态提示，避免报告为已自动移除。
- 确认发布任务同时上传三种包和校验文件，附件版本及摘要和该次 CI 构建一致。
